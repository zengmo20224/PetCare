# 加速交付路线图

更新日期：2026-06-13

## 1. 当前基线

- 后端和管理端已有较多可复用实现。
- 用户端具备 UniApp H5 构建能力，但核心流程尚未全部真实联调。
- 商品订单和社区后端能力已有基础，应优先接通，而不是重写。
- 营销活动有基础数据模型，缺少完整可用流程。
- AI 代码已实现，V1 部分激活（D-004 修订：客服对话 + 经营分析报告接 DeepSeek），V2 Agent 增量（D-013：PgVector RAG + Agent 工具调用 + 社区/审核）已立设计基线，按 M8 切片落地。
- 当前已知风险：认证过滤器对格式错误的 `Authorization` 请求头可能降级为匿名访问，必须在进入登录后 H5 流程前修复。

## 2. 交付顺序

### M0：定位与流程重置

目标：建立 H5 优先、少文档、纵向切片的单一执行基线。

完成条件：

- 核心文档完成合并。
- 旧阶段 brief、review 和 handoff 文档从工作区移除。
- Agent 以后不再创建同类文档。

### M1：H5 基础与可重复演示数据

目标：任何开发者都能启动后端和 H5，并看到稳定、可联调的数据。

任务：

- 修复认证请求头已知风险。
- 建立可重复执行的演示种子数据。
- 验证 H5 构建、路由、API 基址、加载态和错误态。
- 提供仅限开发/验收环境的测试身份入口。

退出条件：H5 可稳定启动，公开数据可浏览，登录后接口可联调。

### M2：公开浏览与营销

目标：未登录用户能完成主要内容浏览。

任务：

- H5 首页、服务、商品、社区和活动列表/详情。
- 基础搜索、分页或筛选。
- 营销活动后台维护和商品/服务关联。
- 公开 DTO 隐私验证。

退出条件：公开 H5 不依赖静态假数据，管理端发布的活动可在 H5 查看。

### M3：用户资料与真实预约

目标：测试身份可完成一条端到端预约。

任务：

- 个人资料、宠物、地址页面和真实 API。
- 服务选择、时段、距离校验、提交预约和预约查询。
- 管理端处理预约状态。
- 预约并发和状态流转验证。

退出条件：一次预约能从 H5 创建并在管理端正确处理。

### M4：真实商品与订单

目标：商品到订单的完整流程可真实使用。

任务：

- 商品详情、购物车、提交订单和订单查询。
- 服务端金额、商品快照、库存和幂等验证。
- 管理端处理订单状态。
- 关键订单流程 E2E。

退出条件：订单流程使用真实数据和事务规则，不依赖前端计算金额。

### M5：简化社区

目标：交付够用且安全的社区互动。

任务：

- 发帖、浏览、点赞、评论和收藏。
- 用户内容权限、公开隐私和基础审核。
- 移除或隐藏超出范围的复杂社交入口。

退出条件：核心互动可重复验证，用户之间无私有信息泄露。

### M6：发布收口

目标：形成可演示、可继续迭代的 H5 V1。

任务：

- ~~关键流程回归、响应式检查和错误体验修复。~~ 已完成
- ~~全量后端/前端测试、构建和关键 E2E。~~ 已完成
- ~~清理仅限开发环境的入口和测试数据风险。~~ 已完成
- ~~确认 H5 正式公开登录方案后再进入公开试运行。~~ 已完成（手机号+密码，安全问题找回）

## 3. 延后队列

- 微信登录和小程序适配。
- **AI 功能的进一步激活与真实 LLM 接入**：V1 部分（客服对话、经营分析）已在 D-004 激活；V2 AI Agent 增量（向量库 RAG、Agent 工具调用、社区助手、内容审核）已进入 M8 切片，设计基线见 `docs/09-ai-agent-design.md`，决策见 D-013。
- **真实在线支付通道**（微信/支付宝等第三方资质接入）、优惠券、会员积分、多门店和复杂营销。注：钱包余额属管理端台账，已在 CR-20260718-003 进入 M7 切片，不属于"在线支付"范畴。
- 钱包营销赠送规则（如"充100送20"）、用户自助充值、提现/转账、退款审批流。
- 非关键报表和大规模视觉重构。

## 3a. M7 钱包余额切片（CR-20260718-003）

> 目标：在无第三方支付资质的场景下，通过管理端手工台账验证商品订单与服务预约的完整支付链路（含金额、库存、并发、状态、审计）。详细边界见 `docs/08-pending-decisions.md` D-010/D-012。

- 阶段 0：合规治理（CR 申请单 + 修订 D-010 + 新增 D-012 + 同步 boundary/architecture/登记表）。
- 阶段 1：`user_wallet` / `wallet_transaction` 表 + Wallet Entity/Mapper/Service + 枚举与错误码 + WalletServiceTest/WalletConcurrencyMySqlIT。
- 阶段 2：商品订单与服务预约下单/取消接入钱包扣款与退款 + WalletPaymentAtomicityIT/WalletRefundAtomicityIT。
- 阶段 3：AdminWalletController + UserWalletController + RBAC 权限码 + 审计范式 + AdminWalletControllerTest/AdminWalletAuditRollbackTest。
- 阶段 4：miniapp `pages/wallet` 分包 + 订单结算页接入钱包支付 + 预约页钱包选项。
- 阶段 5：admin-web 钱包管理菜单（账户列表 + 流水查询）+ 操作日志字典。
- 阶段 6：测试验证与全量回归（单元 + 真实 MySQL 并发 IT + E2E 验收 7 项）。
- 阶段 7：归档（CR 实施记录 + 登记表 + CHANGELOG + 决策记录已实现清单）。

## 3b. M8 AI Agent 切片（D-013 / `docs/09-ai-agent-design.md`）

> 目标：把 V1 无状态客服升级为可检索（RAG）+ 可行动（Agent 工具调用）的 AI Agent，并激活社区助手与内容审核。向量库选 PgVector（独立 PG 实例），LLM 框架引入 langchain4j 作为 `AiProviderClient` 端口的实现层。详细设计与边界见 `docs/09-ai-agent-design.md`，选型决策见 D-013。

- M8.0 基建：langchain4j + PgVector + embedding + 知识入库（离线索引）。
- M8.1 客服 RAG 升级：客服接 RAG + Tool 白名单（只读）+ SSE 流式 + 流式护栏。
- M8.2 经营分析下钻：AnalyticsAgent + 只读 Tool + 结构化报告。
- M8.3 社区助手激活：解除 401 + PostAssistantAgent + 文本审核 Agent（产 PostReport 不直接删）。
- M8.4 图片审核：ONNX Java 原生 nsfw 推理（无 Python sidecar）+ 图片审核 Agent。
- M8.5 收口：全量回归 + AI 用量查看页 + 文档归档。

## 4. 任务切片规则

- 每个 Agent 领取一个能独立演示和验证的纵向切片。
- 默认直接完成实现、测试、Review 修复和交接。
- 不为任务新增阶段计划文档；新的重要决定只更新现有核心文档。
- 先复用现有代码，再补缺口；发现旧实现有风险时在当前切片内修复。

## 5. 完成定义

一个切片只有同时满足以下条件才算完成：

- 用户流程真实可运行。
- 后端业务规则和权限生效。
- 相关自动化测试与构建通过。
- 关键失败路径有明确错误反馈。
- `git diff --check` 通过，未覆盖无关变更。
