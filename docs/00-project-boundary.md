# 项目边界

## 1. 当前定位

PetCare O2O V1 是单门店、模块化单体、H5 优先的宠物门店业务应用。

- 用户主入口：响应式 H5 Web。
- 管理入口：PC Web。
- 微信登录和小程序：后续兼容目标。
- AI（V1，D-004 修订 2026-07-21）：用户端智能客服对话 + 管理端经营分析报告接入真实 DeepSeek；`AiProviderClient` 端口 + 三层医疗护栏 + 架构守卫。
- AI（V2，D-013，**M8.0-M8.3/M8.5 已实施，2026-08-14**）：PgVector RAG + Agent 受限工具调用（客服/经营分析/社区助手三类 Agent）+ 文本内容审核（产 PostReport 不直接删）+ SSE 流式（H5）+ AI 用量查看页。**M8.4 图片 NSFW 审核延后**（ONNX 推理，独立切片再启）。AI 不直连 DB、不做疾病诊断/处方/治疗承诺的硬边界全部保留并由守卫测试强制。

## 2. 当前必须保留的业务

- 用户资料、宠物档案和地址。
- 服务展示、预约、排班、距离和并发控制。
- 商品、购物车、订单金额、库存和状态流转。
- 社区发帖、浏览、点赞、评论、收藏和基础审核。
- 基础营销活动的展示、管理及商品/服务关联。
- 管理端权限和业务处理。
- **AI 智能客服对话**（用户端，CUSTOMER_SERVICE / PET_CHAT 两种会话类型，多轮上下文，接入 DeepSeek）与 **AI 经营分析报告**（管理端，BUSINESS/COMMUNITY/SALES/ACTIVITY 四种类型）。详见 D-004 修订（2026-07-21）。

## 3. 当前明确不做

- 微服务、多门店和独立员工端。
- **真实在线支付通道**（微信支付、支付宝等第三方支付资质接入）、**退款到外部账户**、优惠券、会员积分和配送系统。注：钱包余额不属于此范畴——它是管理端手工台账（详见 D-010/D-012），不接入第三方支付、不计息、不可提现、不可转账。
- 用户自助充值（充值仅由管理员后台单向操作）。
- 钱包营销赠送规则（如"充100送20"，本期仅预留 `BONUS` source_type，不实现）。
- 复杂社交关系、私信、推荐算法和直播。
- ~~V1 不开放 AI 社区发帖助手与 AI 用量查看页~~ **已解除（M8.3/M8.5，2026-08-14）**：发帖助手已激活（仅生成草稿不自动发布）、AI 用量查看页已上线（`ai:usage:read` 权限）。内容审核为"AI 建议 + 人工处置"，不自动删帖。图片 NSFW 审核（M8.4）延后。
- 宠物疾病诊断、药物处方或治疗承诺（AI 安全硬约束，永久不做）。

## 4. 不得改变的核心规则

- 价格、库存、订单金额、预约容量和状态流转由服务端决定。
- 商品下单和多表状态变更必须使用事务。
- 预约必须校验距离、时段容量、重复提交和并发冲突。
- 用户只能访问和修改自己的私有数据。
- 公开接口必须使用专门的公开响应模型，不能直接暴露内部实体。
- 管理权限必须由后端强制执行。
- 所有外部输入必须校验，所有秘密必须来自安全配置。

## 5. 范围变更

新增功能只有在直接支持当前 H5 核心流程或修复真实风险时才能进入 V1。任何会引入新平台、新支付链路、新业务角色或复杂运营规则的需求，先记录到 `docs/08-pending-decisions.md`，不得顺手实现。
