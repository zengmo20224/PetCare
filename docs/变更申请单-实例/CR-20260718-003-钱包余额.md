## 二、变更内容描述

### 2.1 现状

项目当前**完全不存在在线支付链路**，且被 D-010 显式排除在 V1 范围之外：

- D-010（`docs/08-pending-decisions.md`）：不接在线支付、优惠券、积分和多门店。
- `docs/00-project-boundary.md` §3：当前明确不做"在线支付、退款、优惠券、会员积分和配送系统"。
- 商品订单 `paymentMethod` 在 `ProductOrderTransactionServiceImpl.java:209` 硬编码为 `OFFLINE_STORE`；管理员"确认支付"按钮仅做 `paymentStatus` 字段翻转（`UNPAID → OFFLINE_PAID`），不调用任何支付通道。
- 服务预约 `BookingApplicationServiceImpl.createBooking` 接收 `paymentMethod` 入参但仅落库，无任何资金动作。
- `pom.xml` 无支付 SDK；`schema.sql` 51 张表中无任何 wallet/account/balance/transaction 类表；`admin_permission` 无 wallet 相关权限码。
- 现状带来的问题：在没有微信支付商户号等第三方支付资质的课程演示/自测场景下，无法端到端验证"下单 → 支付 → 状态翻转"链路；无法演示后续"充100送20"等营销活动；无法证明订单金额事务、库存防超卖、并发幂等等高风险规则在带支付的真实链路下仍然成立。

涉及的配置项：CI-DB-001（主 schema）、CI-SC-001/002（后端源码与测试）、CI-SC-005/006（前端源码与测试）、CI-DOC-012（决策记录）、CI-DOC-013（需求基线）。

### 2.2 期望

引入"**钱包余额**"作为管理端手工台账，用于无支付资质下的支付链路验证：

1. **新增 `user_wallet` 账户表**（user_id 唯一，balance DECIMAL(10,2)，含乐观锁 version）与 **`wallet_transaction` 流水表**（只追加，含 before/after 余额、direction、source_type、related_order、operator、idempotency_key）。
2. **新增 `com.petcare.wallet` 模块**：Entity / Mapper（行锁 + 条件 UPDATE）/ Service / Controller / DTO。
3. **商品订单与服务预约两条链路接入钱包支付**：下单时若选 `WALLET`，钱包扣款与库存/容量扣减必须在同一事务（满足"不能扣了钱没扣库存，或反之"的硬性要求）；取消时事务内自动退回钱包（type=REFUND 流水）。
4. **管理端钱包操作 API**：充值、双向调整（每次必须填理由并强制审计，照 booking 范式：成功审计失败抛 IllegalStateException 触发回滚，失败审计走 REQUIRES_NEW 保活，未知异常脱敏为 `unexpected_error`）。
5. **用户端只读 API**：用户可查看自己的余额与流水，但不能自助充值（充值仅由管理员后台操作）。
6. **前端**：miniapp 新增 `pages/wallet` 分包（余额卡片 + 流水查询），订单结算页与预约创建页新增"钱包支付"切换；admin-web 新增钱包管理菜单（账户列表 + 流水查询）。
7. **RBAC**：新增 `wallet:account:{read,recharge,adjust}`、`wallet:transaction:read` 权限码，绑定 SUPER_ADMIN。

### 2.3 变更理由

- **业务诉求**：用户当前无微信支付商户号等支付资质，无法接入真实在线支付；但又需要端到端验证购买支付链路（含金额、库存、状态、并发规则）。钱包余额作为管理端手工台账，**零外部资质依赖**即可完整演示下单→支付→状态翻转闭环。
- **可演进性**：钱包账户与流水表的设计与未来真实接入微信支付完全兼容——未来只需把"管理员手工充值"的入口替换为"微信支付回调写流水"，数据模型不变，本次工作量不被浪费。
- **风险驱动**：钱包扣款天然复用项目已成熟的事务/行锁/幂等/BigDecimal/审计基础设施（product/booking/admin 模块已验证），不引入新的并发范式。
- **合规边界**：本变更**不引入**真实在线支付通道、优惠券、会员积分、提现、转账、跨门店、营销定价规则，仅在 D-010 边界内开一个"管理端台账"口子，且不计息/不可提现/不可转账/不参与复杂价格计算。

**代码规模**：新增 31 个文件，修改约 15 个既有文件。

- 4 个枚举（WalletDirection / WalletSourceType / WalletOperatorType / RelatedOrderType）
- 2 个实体（Wallet / WalletTransaction）
