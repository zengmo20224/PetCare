> 本文档是一版**基于微信小程序原生组件**的全新 UI 设计稿，覆盖 PetCare 用户端所有界面。

> 适用：另一个开发者看完本文档，应能照着用微信原生组件（view/text/image/button/swiper/scroll-view 等）+ iconfont 复刻实现。

## 一、设计语言

### 1.1 整体风格定位

**定位：微信原生简洁风（信息优先、克制的品牌化）。**

| 维度 | 当前 H5 方案 | 本方案（微信原生风） |
|------|------------|------------------|
| 视觉重心 | 大圆角卡片、装饰渐变光斑、英文 kicker | 白底卡片、细线分隔、留白克制 |
| 圆角 | 32rpx ~ 44rpx（偏大） | 8rpx ~ 16rpx（贴近微信原生） |
| 装饰 | radial-gradient 光斑、彩色图标方块 | 去装饰，靠留白和分隔线组织信息 |
| 字体 | 18rpx 英文 kicker + 40rpx 大标题 | 微信原生层级（32rpx 标题 / 28rpx 正文） |
| 图标 | emoji + wd-icon 混用 | iconfont 统一线性图标（情感场景保留 emoji） |
| 信息密度 | 偏低（每屏卡片少） | 适中（更符合小程序使用习惯） |
| 组件依赖 | wot-design-uni（wd-button/wd-card/wd-tag...） | 纯原生（view/text/image/button...） |

核心原则：
1. **能用原生就不用自绘**——导航栏、tabBar、按钮、表单 picker 走原生能力。
2. **信息密度 > 装饰**——卡片靠 1rpx 细线和留白分隔，不用大阴影。
3. **品牌色克制使用**——青绿只出现在主操作、选中态、关键金额，不做大面积铺色。
4. **图标统一线性**——全部用 iconfont 单色线性图标，保证视觉一致。

### 1.2 色彩系统

保留品牌青绿 `#11796F`（不强行换成微信绿 `#07C160`，避免与微信系统色混淆），但中性色阶重新校准到更贴近微信原生的灰度体系。

#### 主色（品牌青绿）

| 色值 | 用途 | 说明 |
|------|------|------|
| `#11796F` | 主操作 / 选中态 / 主链接 | 按钮、tab 选中、关键金额 |
| `#0C4D48` | 主色按下态 / 深色文字 | 按下 hover、品牌深色 |
| `#DFF2ED` | 主色浅底 | 选中态背景、tag 浅底 |

> 注：导航栏背景仍可用 `#11796F` + 白色文字（与 `pages.json` 现配置一致），保持品牌识别。

#### 功能色

| 色值 | 语义 | 用途 |
|------|------|------|
| `#07C160` | 成功 | 微信原生成功（支付成功、预约确认） |
| `#FA9D3B` | 警告 | 营业中、库存紧张、待确认 |
| `#FA5151` | 危险 | 红点、删除、已取消、余额不足 |
| `#10AEFF` | 信息 | 进行中、链接辅助 |

#### 中性色阶（重新校准，贴近微信）

| 色值 | 层级 | 用途 |
|------|------|------|
| `#1A1A1A` | 标题文字 | 一级标题、商品名、金额 |
| `#333333` | 正文文字 | 正文、列表主文案 |
| `#666666` | 次要文字 | 描述、副标题 |
| `#999999` | 辅助文字 | 时间、备注、placeholder |
| `#B2B2B2` | 占位/禁用 | 禁用态、空状态图标 |
| `#E5E5E5` | 分隔线 | 卡片间、列表项间 1rpx 线 |
| `#F7F7F7` | 页面背景 | 全局底色（替代当前米白 `#FAF8F3`） |
| `#FFFFFF` | 卡片背景 | 卡片、单元格底色 |

> 与当前差异：当前用米白 `#FAF8F3` + `#71817D` 灰绿系次要文字；本方案用微信原生 `#F7F7F7` + `#666/#999` 纯灰系，更"微信"。

#### 辅助色（保留少量品牌点缀）

| 色值 | 用途 |
|------|------|
| `#F5A623` | 警告 tag、活动标签（保留自当前） |
| `#E97951` | coral，仅 kicker/小装饰 |
| `#4777C8` | 上门服务图标底色（服务分类色码） |

### 1.3 字体规范

严格对齐微信小程序原生字号（rpx），去掉当前的英文 kicker 设计。

| 层级 | 字号 | 字重 | 行高 | 用途 |
|------|------|------|------|------|
| 特大标题 | `40rpx` | 600 | 1.4 | 钱包余额、Hero 大数字 |
| 页面标题 | `32rpx` | 600 | 1.4 | 章节标题、卡片主标题、商品名 |
| 副标题 | `30rpx` | 600 | 1.4 | 列表项标题、价格 |
| 正文 | `28rpx` | 400 | 1.6 | 正文、描述、按钮文字 |
| 辅助 | `24rpx` | 400 | 1.5 | 标签、提示、时间 |
| 说明 | `22rpx` | 400 | 1.4 | 极小说明、版权、badge |

字体族：`-apple-system, "PingFang SC", "Helvetica Neue", Helvetica, sans-serif`（小程序默认，无需声明）。

> 与当前差异：当前用 `18rpx` 大写英文 kicker（QUICK ACCESS）+ `40rpx` 中文大标题；本方案**去掉所有英文 kicker**，直接用 `32rpx` 中文标题，更符合微信小程序习惯。

### 1.4 间距系统

8 的倍数 rpx 网格。

| Token | 值 | 用途 |
|-------|-----|------|
| `--space-xs` | `8rpx` | 图标与文字间隙、tag 内边距 |
| `--space-sm` | `16rpx` | 卡片内元素间距、列表项内小间隙 |
| `--space-md` | `24rpx` | 卡片内边距、章节内元素间距 |
| `--space-lg` | `32rpx` | 页面左右边距、章节间距 |
| `--space-xl` | `48rpx` | 章节大间距、卡片间留白 |

页面左右统一边距 `32rpx`（当前是 `40rpx`，偏大，本方案收紧到微信标准的 `32rpx`）。

### 1.5 圆角规范

大幅收紧圆角，回归微信原生克制风格。

| Token | 值 | 用途 |
|-------|-----|------|
| `--radius-sm` | `8rpx` | 按钮、tag、小方块 |
| `--radius-md` | `12rpx` | 输入框、picker |
| `--radius-lg` | `16rpx` | 卡片、单元格组 |
| `--radius-pill` | `999rpx` | 胶囊按钮、tab pill、FAB（圆形） |

> 与当前差异：当前卡片圆角 `32rpx ~ 44rpx`（偏胖）；本方案卡片 `16rpx`，按钮 `8rpx`，更利落。仅胶囊 tab 和 FAB 保留全圆。

### 1.6 图标方案

**主方案：iconfont 单色线性图标（24rpx / 32rpx / 48rpx 三档）。**

- 推荐图标库：iconfont「微信小程序官方示例」风格线性包，或 Ant Design Mini 线性图标集。
- 颜色：默认 `#666666`，选中/激活 `#11796F`，危险 `#FA5151`。
- 尺寸：tabBar `48rpx`，列表项 `32rpx`，按钮内 `24rpx`，空状态 `96rpx`。
- 用法：用 `<image>` 引入 iconfont 下载的 PNG/SVG，或用 `<text>` 配 `font-family: iconfont`（需在 `app.vue` 引入字体）。

**辅方案：emoji 仅用于情感化场景**（社区点赞 ❤️、收藏 ⭐、公告 📢、空状态 🐾），不用于功能导航图标。

> 与当前差异：当前 emoji 和 wd-icon 混用，视觉不统一；本方案功能图标全部线性 iconfont，emoji 仅保留在社区/空状态的情感场景。

### 1.7 阴影与分隔

**克制使用阴影，优先用细线分隔。**

| Token | 值 | 用途 |
|-------|-----|------|
| `--shadow-none` | 无 | 卡片默认无阴影，靠 `border-bottom: 1rpx solid #E5E5E5` |
| `--shadow-card` | `0 2rpx 8rpx rgba(0,0,0,0.04)` | 仅悬浮元素：FAB、底部操作栏、弹出层 |
| `--shadow-popup` | `0 -4rpx 16rpx rgba(0,0,0,0.08)` | 底部弹起的 picker / action sheet |

分隔线规则：
- 列表项之间：`border-bottom: 1rpx solid #E5E5E5`（最后一项无线）。
- 卡片之间：纯留白 `24rpx`，无线无阴影。
- 章节之间：留白 `32rpx`。

> 与当前差异：当前用 `0 8rpx 24rpx rgba(25,50,46,0.08)` 大投影卡片；本方案默认无阴影、细线分隔，仅 FAB/操作栏有轻投影，更贴近微信原生列表观感。

- 公告条：`<view>` 单行，`text-overflow: ellipsis`

- 精选好物：`<scroll-view scroll-x>`，内部 `view` 卡片横向排列
- 社区动态：纵向 `<view>` 列表
- AI 入口：`<view>` 整块可点

- 所有卡片 `#FFFFFF`，无阴影，靠 `24rpx` 留白分隔

- 公告条点击 → `/pages/announcement/detail?id=`

- 精选好物卡点击 → `/pages/products/detail?id=`
- 活动卡点击 → `/pages/activity/detail?id=`
- 帖子卡点击 → `/pages/community/detail?id=`
- AI 入口卡点击 → `/pages/ai/chat`
- 所有可点元素：`hover-class` 背景变 `#F7F7F7`，无缩放动画

**与当前设计差异**：
1. **去掉 Hero 大渐变卡**（当前 PcHeroCard 是青绿渐变 + 大 CTA 按钮），改为顶部"门店信息条"，更轻量、信息更直接。

3. **快捷入口圆角从 `34rpx` 收到 `16rpx`**，图标块从 `104rpx` 收到 `96rpx`。
4. **卡片无大阴影**，靠留白分隔，信息密度提升。
5. **精选好物卡变窄**（`240rpx` vs 当前 `380rpx`），单屏可见更多商品。

### 2.2 服务预约 services/index

├─────────────────────────────────────────┤

### 7.4 与当前 H5 设计的总体差异和建议

#### 主要差异对照

| 维度 | 当前 H5 方案 | 本方案（微信原生风） |
|------|------------|------------------|
| **组件库** | wot-design-uni（wd-button/wd-card/wd-tag/wd-input...） | 纯原生 view/text/image/button/picker/swiper |
| **页面背景** | 米白 `#FAF8F3` | 微信灰 `#F7F7F7` |
| **次要文字** | 灰绿 `#71817D` | 纯灰 `#666/#999` |
| **卡片圆角** | `32rpx ~ 44rpx` | `16rpx` |
| **按钮圆角** | `12rpx ~ 16rpx`（wot）/ 胶囊 `1998rpx`（自绘） | `8rpx`（统一） |
| **卡片阴影** | `0 8rpx 24rpx rgba(25,50,46,0.08)` 大投影 | 无阴影，靠 `1rpx` 分隔线 + 留白 |
| **Hero 卡** | 青绿渐变 + 大 CTA + radial-gradient 光斑 | 取消，改为信息条 |
| **英文 kicker** | QUICK ACCESS / PET SELECT / SHARE THE MOMENTS（18rpx 大写） | 全部去掉，纯中文标题 |
| **图标** | emoji + wd-icon 混用 | iconfont 线性统一（emoji 仅情感场景） |
| **价格色** | 橙 `#F5A623`（部分）/ 珊瑚 `#E97951` | 红 `#FA5151`（电商习惯） |
| **成功色** | wot `#34d19d` | 微信 `#07C160` |
| **页面边距** | `40rpx` | `32rpx`（微信标准） |
| **底部导航** | H5 自绘 PcBottomNav / 小程序原生 tabBar | 统一用原生 tabBar |
| **信息密度** | 偏低（大卡片少内容） | 适中（细线分隔多内容） |

#### 建议采纳的点

1. **圆角统一 `16rpx` 卡片 / `8rpx` 按钮**——更利落，符合小程序审美。
2. **去装饰渐变和光斑**——减少视觉噪音，提升信息密度。
3. **去英文 kicker**——小程序用户更熟悉纯中文标题。
4. **价格统一红色 `#FA5151`**——符合电商认知。
5. **成功色用微信绿 `#07C160`**——与系统一致。
6. **图标全部 iconfont 线性**——视觉统一。
7. **中性色用微信灰阶**（`#1A1A1A/#333/#666/#999/#E5E5E5/#F7F7F7`）——更"微信"。
8. **单元格组用细线分隔**——替代大投影卡片，信息密度更高。
9. **底部操作栏/提交栏固定**——详情/表单页转化更稳。
10. **底部导航统一原生 tabBar**——H5 端可保留自绘，但小程序端务必用原生。

#### 可保留的当前设计优点

1. **品牌青绿 `#11796F`**——辨识度高，本方案保留。
2. **快捷入口彩色图标块**（洗护青绿/美容橙/上门蓝/寄养粉）——本方案保留这套色码。
3. **社区图片自适应网格规则**（1/2/3/4/5/6 张布局）——本方案沿用。
4. **钱包余额卡渐变**——作为品牌色高光场景保留。
5. **空状态的 emoji + 主副文字 + CTA 结构**——本方案沿用并标准化。

#### 实施建议

- **本方案是参考稿**，不强制替换现有 H5 设计；建议在小程序端试点，对比数据后再决定是否全量。
- 若决定落地，建议：
  1. 先做一套全局 CSS 变量（对应 `tokens.css` 新增 `mp-native` 主题），通过条件编译切换。
  2. 逐页替换：先 5 个 Tab 主页，再详情页，再流程页。
  3. 图标统一接入 iconfont 字体，减少 image 请求。
  4. 表单类页面优先用原生 `picker`/`input`，替换 wd-input。
  5. 底部导航 H5 端保留 PcBottomNav，小程序端确认用原生 tabBar（当前已配 `tabBar`，但 H5 用自绘，需双轨）。
